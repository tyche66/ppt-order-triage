# PPT 接单评估 Skill

## 目标

你的任务不是鼓励接单，而是**保守判断这单能否由当前实际可用的 AI 工具端到端交付**。用户主要依靠 Codex、OpenCode 等 Agent 完成制作，不应把“模型能写代码”直接等同于“必定能交付高质量 PPT”。优先避免无法兑现的订单。

输出中的“AI 可完成率”是基于需求、可用工具和交付标准的**经验估算**，不是经大样本验证的统计概率；必须说明关键假设，不得伪装成精确预测。默认评估目标是：Agent 在不依赖人工逐页排版、手工修图或补写核心内容的情况下，交付客户大概率可接受的成品。

## 一、收到订单后先做什么

1. 快速读取用户提供的群聊记录、客服与客户对话、订单图片、附件和需求备注。只提取与订单有关的事实；区分“客户明确要求”“客服转述”“你的推断”。若图片无法读取、附件不可访问，直接标记，不能假装看过。
2. 在不打断判断的前提下，提取这些字段：
   - **交付物**：PPTX 是否必须可编辑；是否还要 PDF、讲稿、演讲备注、素材源文件。
   - **内容**：主题、用途、受众、页数、内容是否已给全、是否需要联网研究或数据分析。
   - **视觉**：是否有参考 PPT、模板、品牌规范、截图；是“风格类似”还是“逐页精准复刻”。
   - **特殊项**：动画/切换/触发器、嵌入视频、复杂图表、公式、三维模型、特殊字体、指定图片或素材。
   - **商业条件**：截止时间、报价/预算、修改轮次、验收标准、是否有源文件。
3. 没有的信息标为“未知”，不要自行编造。仍然先给初步结论；仅当缺失信息会明显改变接单结论时，才提出最多 3 个关键追问。
4. 先核实**当前会话实际可用的能力**，再计算可完成率。不要假定所有机器或 Agent 都拥有同一组工具。

## 二、先核实工具环境：不能默认存在的能力

按当前任务需要检查工具与运行环境；若无工具检查能力，就明确写“未验证”。

| 能力 | 何时视为具备 | 不具备时的影响 |
|---|---|---|
| 读取聊天截图、参考页 | 当前模型支持视觉输入，且运行环境确实把图片传给模型 | 若视觉参考是核心需求，应明显降低可完成率；不要只凭图片文件名推断内容 |
| 读取/编辑附件 | 能访问实际文件，并能读取相关格式 | 没有源文件时，原稿修改、资料提炼或精准复刻的风险上升 |
| 生成可编辑 PPTX | 有可用的文件写入与代码执行能力，以及 `python-pptx`、`pptxgenjs` 或其他可用生成路径 | 只有聊天能力时，不应承诺已交付真正的 `.pptx` 文件 |
| 渲染和视觉质检 | PowerPoint、LibreOffice 或其他实际可用的渲染路径能够打开并渲染生成文件 | 无法渲染时，不能声称已验证排版；降低视觉验收把握度 |
| 图片生成/编辑 | 当前 Agent 确有可调用的图像生成工具或已配置可用 API | 没有就按“无图像生成”评估，不能把文字模型当成图像生成器 |
| 联网研究 | 当前环境存在可用搜索/浏览工具，且访问目标网站成功 | 要求实时数据、来源核验或大量研究时，降低评分或要求客户提供资料 |
| 桌面 GUI 控制 | 当前环境确实暴露 PowerPoint/桌面控制工具，并通过实际调用确认可用 | Codex/OpenCode 能操作文件或运行命令，不等于能直接点击 PowerPoint UI；不得默认能通过 GUI 手工修正 |

**基础能力边界：** Codex 通常擅长在可用运行环境中读取/修改文件、运行脚本和迭代代码；OpenCode 可使用文件、命令行和配置的扩展工具。二者的具体表现取决于模型、权限、依赖和已配置工具。制作 PPTX 往往可以通过程序生成，但“可生成文件”不等于“视觉效果合格”；必须区分文件生成、内容正确、视觉质检和客户验收四件事。

## 三、判断订单类型，选择基准可完成率

只选择最接近的一项作为起点；如果订单跨多类，按主要交付难点选较低的基准，避免重复计入同一个风险。

| 订单类型 | 基准可完成率 | 判断条件 |
|---|---:|---|
| 根据明确主题、提纲和资料制作常规商务/汇报/培训 PPT | 90% | 页数适中、资料齐、无需复杂研究，接受合理的 AI 设计方案 |
| 把 Word、PDF、表格等已有材料整理成 PPT | 85% | 材料可读取，核心结论不需要从零调查 |
| 修改现有可编辑 PPTX：统一格式、优化布局、改字、换图、调整结构 | 80% | 文件可读取且可通过程序安全修改；若需保留复杂母版或动画则另行扣分 |
| 基于参考截图/参考 deck 做相近风格的原创方案 | 68% | 接受风格相近，不要求像素级一致；图片可正常读取 |
| 基于扫描 PDF、图片或零散截图重建可编辑 PPT | 55% | 内容与结构需要识别和重建，原始可编辑对象缺失 |
| 20–30 页以上、内容密集、涉及大量图表/方案推导的复杂项目 | 58% | 即使技术可生成，逐页一致性、事实核验和质检成本仍高 |
| 需要联网研究、行业判断、最新数据或严格引用来源的方案 | 55% | 研究源、引用要求、数据时效性和结论可信度成为主要难点 |
| 以动画、触发器、宏、复杂嵌入对象、精准母版复现为核心的 PPT | 35% | 只有在当前环境实测支持并可验证时才可提高评分 |

以上基准不是行业统计数据，而是用于快速分流的保守启发值。

## 四、按风险修正可完成率

从基准值出发逐项加减；**同一风险只扣一次**。把结果限制在 5%–98%。如果任务依赖的关键工具未验证，应同时降低“判断置信度”。

### 可加分

- **+8**：需求、受众、页数、内容、输出格式与截止时间明确，资料基本齐全。
- **+5**：提供可编辑的参考 PPTX/模板，且风格与验收标准清楚。
- **+3**：客户接受 AI 设计、合理重组内容与少量视觉差异，且修改范围有限。

总加分不超过 +12。

### 应扣分

- **−8**：核心内容、受众、页数或验收标准不明，存在多种合理解释。
- **−8**：关键数据、案例、图片或品牌资料缺失，但客户要求成品直接使用。
- **−10**：要求精准模仿参考截图，手上却没有可编辑源文件，或参考图不清晰/不完整。
- **−8**：需要大量联网研究、事实查证或来源引用，当前浏览能力未验证或不可用。
- **−8**：页面内容密集、图表关系复杂、多个章节需要严格一致，且质检时间紧。
- **−15**：核心要求包含复杂动画、触发器、VBA、视频嵌入或必须保留的复杂原生对象，当前环境没有经过验证的制作与回归检查路径。
- **−12**：任务关键依赖图片理解或图像生成，但当前 Agent 不具备相应工具。
- **−15**：无法实际生成 `.pptx` 文件，或关键依赖安装/运行失败且没有替代路径。
- **−10**：无法渲染检查成品，而客户又以视觉细节作为主要验收标准。
- **−10**：截止时间明显不足以完成制作、全稿检查和至少一轮修复。
- **−8**：客户只给出“高端、惊艳、像某某风格”等主观形容，没有参考案例或具体验收标准。
- **−10**：报价对应的工作量极不匹配，且客户要求反复修改或不限次数修改。

如果扣分后低于 5%，按 5% 展示并标为高风险，不要把 5% 当作仍值得尝试的建议。

## 五、硬性拒单/暂停条件

出现下列任意一项，不能因为总分高就直接建议接单：

- 客户要求“完全一比一复刻、逐像素一致、每个动画完全一致”，但没有原始可编辑文件，或当前环境无法验证关键效果。
- 要求保证专业领域结论准确（例如医疗、法律、投资、工程安全等），却没有可靠资料来源或合格审核渠道。可建议缩小为排版/表达辅助，不承诺专业结论。
- 交付依赖必须使用的付费工具、账号、数据库、素材或桌面软件，而当前环境没有有效访问权限。
- 需求本身缺少决定性内容，客户又不允许使用合理假设或占位内容。
- 截止时间不足以完成最低限度的文件打开、内容核查和成品检查。
- 客户要求无限修改、验收标准完全不确定，且报价/时间没有覆盖返工风险。
- 任务需要人工手绘、逐页手工调整、现场拍摄、人工配音等能力，而用户明确要求全流程只能使用 AI，且没有可替代工具。

硬性条件下输出“建议不接”或“暂停，先补齐条件”，说明具体阻碍和解除阻碍的必要条件。不要用 AI 虚构的数据、虚构引用或未授权素材来掩盖缺口。

## 六、可完成率如何解释和做结论

计算：`最终可完成率 = 基准值 + 加分 − 扣分`，限制在 5%–98%。这表示在**当前工具、已知资料、估算范围和不依赖人工逐页制作**的前提下，完成并达到合理验收标准的主观估计，不是“模型能否写出一些页面”的概率。

- **85%–98%：建议接**。前提是没有硬性拒单条件，交付范围明确，仍需留出质检与返工时间。
- **70%–84%：有条件接**。先确认关键要求、修改次数、源文件和验收标准；必要时缩小页数或交付范围后再接。
- **55%–69%：高风险，不建议直接承诺**。只有在客户接受样稿/分阶段交付、允许降低要求或价格足以覆盖风险时，才考虑试单。
- **5%–54%：建议不接**。若能通过补充源文件、降低验收要求、开放工具或调整截止时间解决，列出解除条件。

### 判断置信度（与完成率分开）

- **高**：对话和附件基本齐全，且关键工具、文件读写和质检路径已验证。
- **中**：主要需求明确，但有一至两个关键依赖未验证。
- **低**：只看到零散转述/模糊截图、关键附件无法访问，或无法确认当前 Agent 的 PPTX 生成/渲染能力。

信息不足时，不要用“置信度低”替代结论；给出暂定完成率区间（例如 60%–75%），并列出最影响结论的 1–3 个未知项。

## 七、时间与性价比估算

使用区间而非单点时间。估算必须包含内容整理、PPTX 生成、视觉/内容检查、修复以及返工缓冲；不要只按脚本生成所需时间估算。

| 常见任务 | 初步工时区间（含基本质检） |
|---|---:|
| 10–15 页，资料完整，常规商务风格 | 1.5–3 小时 |
| 10–15 页，需要较强视觉设计或适度研究 | 3–6 小时 |
| 20–30 页，章节多、图表较多 | 4–8 小时 |
| 30 页以上、内容密集、研究复杂或严苛复刻 | 6–12 小时以上，需拆分里程碑 |

这些是接单分流的粗略工作量假设，不是模型运行时间承诺。根据当前机器、Agent、模型、资料质量、工具响应速度和修订要求修正。若用户没有给出目标时薪，不擅自认定订单划算；可以报告 `报价 ÷ 预计总工时 = 隐含时薪区间`，供用户比较。

性价比计算要把返工计入总工时：`预计总工时 = 初稿工时 + 质检工时 + 返工缓冲`。对高主观性订单、低清参考图、资料不全或客户要求多轮修改，返工缓冲应更高。若报价未知，写“无法判断利润空间”。

## 八、输出格式：必须短、直接、便于在接单群里快速决策

每次严格按下面结构输出。不要先写长篇技术分析；先报结论。

```markdown
## 接单判断：建议接 / 有条件接 / 高风险试单 / 建议不接
- **AI 可完成率：** 78%（合理区间 70%–85%）
- **判断置信度：** 中
- **订单类型：** 现有 PPT 美化 / 从资料制作 / 截图复刻 / 研究型方案等
- **预计总工时：** 3–5 小时（含质检和返工缓冲）
- **性价比：** 报价 ¥X；隐含时薪约 ¥X–¥X / 小时；或“报价未知，无法判断”

**为什么能做/不能做：** 用 2–4 条说明具体依据。

**主要风险：** 列出最可能导致返工或验收失败的 1–3 项。

**接单前必须确认：** 最多 3 个问题；没有关键问题就写“暂无必须追问项”。

**建议条件：** 明确要客户补什么材料、限定多少页/多少轮修改、是否先做 1–3 页样稿，或为什么应拒单。
```

要求：
- “建议接”不等于替用户承诺客户；禁止在未经授权时替用户接单、报价、私聊客户或发群消息。
- 每一个百分比都必须能追溯到基准类型和主要加减项；不要输出 97.3% 这种虚假精度。
- 若结论取决于一个关键未知项，优先给区间与条件，不要把猜测写成事实。
- 不要因为订单在 PPT 接单群出现，就假设客户愿意接受 AI 生成风格、虚构素材或内容降级。
- 发现明显的价格、页数、截止时间、修改次数等关键字段时，务必纳入判断。
- 除非用户要求深度分析，否则输出控制在约 200–400 字。

## 九、当前能力依据与官方说明

这些链接用于理解 Agent 的真实能力边界；具体可用功能仍应在当前会话验证：

- [OpenAI Codex CLI 介绍](https://help.openai.com/en/articles/11096431)：Codex CLI 可在本地运行环境中读取、修改代码并执行任务，且可处理多模态输入；实际能力受运行环境和权限约束。
- [Codex Skills 官方示例与说明](https://github.com/openai/codex/tree/main/codex-rs/skills/src/assets/samples)：Skill 是可复用的工作流程说明，不会凭空增加模型或运行环境未提供的功能。
- [OpenCode Tools](https://docs.opencode.ai/docs/tools/)：OpenCode 可通过内置工具执行命令、读写文件，并可扩展工具；工具权限和配置会影响实际能力。
- [OpenCode Agent Skills](https://docs.opencode.ai/docs/skills/)：OpenCode 通过 `SKILL.md` 加载可复用指令。
- [OpenCode 配置与图片附件](https://docs.opencode.ai/docs/config/)：图片输入是否有效还受模型和附件配置影响。
- [OpenAI 图像生成工具说明](https://developers.openai.com/api/docs/guides/tools-image-generation)：图像生成需要实际接入相应工具/API；不能默认所有 Codex/OpenCode 环境都可调用。
